# Рабочие исходники SCROLL

Каталог `src` содержит основной модульный AHDL-проект SCROLL для EP1K30QC208-3. Он получен из авторских исходников BASE и сопоставлен с проверенным владельцем на плате проектом `../net_list`. После переноса владельцем `src` уже не является исходным BASE. Исторический BASE сохранён в коммите `06b1617`; локальный снимок — `../work/author_scroll_20261031/inputs/src`.

**Исправление переноса от 01.11.2026: переносить нужно весь набор входов проекта — TDF, INC, MIF и ACF. Одного копирования TDF недостаточно. В SCROLL изменены также `DCP.MIF` и `SCROLL.ACF`; оставлять вместо них старые файлы BASE нельзя.**

| Обязательный файл | Что должно быть в SCROLL |
|---|---|
| `DCP.MIF` | Слово по адресу `EE` равно `2041h`; прежнее значение BASE `2000h` не соответствует эталону SCROLL. Остальные 255 слов таблицы совпадают |
| `SCROLL.ACF` | Проверенный SCROLL-профиль устройства, пинов и настроек компилятора. Это замена всего профиля, а не одна правка направления XA3. Старые назначения удалённого AY и прежних внутренних узлов BASE сюда не переносятся |

При исправлении восстановлены только эти два входных файла. Пользовательское имя `AY_CHS`, прочие HDL и удаление лишних модулей сохранены. Снимки до исправления, хеши, проверка всех 13 входов и результаты сборок находятся в `../work/transfer_repair_20261101`.

## Состав проекта

| Файл | Назначение |
|---|---|
| `SCROLL.TDF` | Связи модулей, CPU/DRAM-интерфейс, CBL/PCM, системные регистры и синхронизация |
| `VIDEO2.TDF` | Растр, сетка и команды аппаратного сдвига, описатели, адреса картинки, пиксельный и палитровый конвейеры, VRAM |
| `DCP.TDF`, `DCP.MIF` | Декодирование, трансляция памяти/портов, ожидания и исходная таблица |
| `ACCELER.TDF` | Авторский байтовый акселератор с DOOM-путём; сохранена технологическая форма инкременторов и AA_LOAD15 |
| `KBD.TDF`, `KBD_INI2.MIF` | Клавиатурный приёмник и исходная таблица |
| `MOUSE.MIF` | Зависимость декларации неактивной ROM VIDEO: компилятор читает MIF до удаления ветки MOUSE=NO; мышь в SCROLL не реализуется |
| Четыре `*.INC` | Интерфейсы модулей; порядок, разрядности и параметры соответствуют текущим TDF |
| `SCROLL.ACF` | Назначения и настройки проверенного SCROLL-профиля |

Top-level — `SCROLL`; его функция здесь — SCROLL. Проверяемые параметры: `UPDATE=1`, `MODE="SPRINTER"`, `NMI_ON="OFF"`. Унаследованный SCREEN_OFF не выбирает гашение SCROLL: оно подключено к RGMOD.bit2 по эталону. Все уравнения AHDL описывают одновременно работающую аппаратуру.

TDF/MIF сохранены в исходной кодировке авторского проекта (CP866 там, где есть не-ASCII текст); INC — ASCII, ACF и этот README — UTF-8. Правило UTF-8 для `SP_Conf_Test/altera/acex` не меняет кодировку этого отдельного проекта.

## Читаемая форма исходников

Сохранены авторские модули, шины, счётчики и декларации памяти. CBL остаётся `256x16`, а RAM акселератора сохраняет ширину 16 с дублированным байтом; неиспользуемые разряды удаляет компилятор. Исходники намеренно не превращены в оптимизированный плоский нетлист.

Новые состояния VIDEO названы GRID_X/Y, SHIFT_X/Y, MODE3 и другими именами по назначению. В верхнем модуле владелец сохранил имя `AY_CHS`: в текущем SCROLL это стадия выборки PCM, штатный синтезатор AY этим именем не возвращается. В предыдущем пакете эта же стадия называлась AUDIO_CHS.

Физические границы адресного тракта записаны через VLA_NEXT и две группы VLA_MUX/VLA_HOLD по 11 LCELL для VLA[17..10] и VLA[4..2]. Остальные семь разрядов соединены напрямую. AA_INC/AGR_INC выражены через FOR GENERATE и проверку младших разрядов на единицы. Это форма записи существующей схемы, без дополнительных регистров и без пустых ячеек ради числа LC.

## Изолированная компиляция текущего src

В VS Code выберите задачу **Compile SCROLL (src)**. Прежняя задача Compile Scroll.tdf собирает net_list и сохранена отдельно. Новый пункт вызывает bin/build_src.py: создаёт свежий изолированный запуск MAX, проверяет trace, преобразует TTF штатным TransTTF и сверяет все байты ACX. После успешной проверки результат сохраняется в `Build/SCSRC/SCROLL.ACX`, рядом — SCROLL.TTF, SCROLL.SOF, SCROLL.RPT и BUILD.JSN с привязкой к запуску и хешами.

Та же команда из корня Scroll_CNF:

```powershell
C:\Python312\python.exe -X utf8 -B bin\build_src.py
```

Build/SCSRC выбран отдельно от прежнего Build/scroll; в Windows Build/SCROLL был бы тем же каталогом, что Build/scroll. Build/SCAUTH31 также сохраняется. Имя AHDL-проекта в настройке ahdl.projectFile рабочего пространства — src/SCROLL.TDF.

Для отдельного запуска launcher без публикации ACX используются команды из корня Scroll_CNF:

```powershell
C:\Python312\python.exe -X utf8 -B bin\maxplus2_isolated.py --source src --acf src\SCROLL.ACF --top SCROLL
```

Launcher создаёт новый `temp_max_run/mp2_runs/<unique>` с реальными копиями входов, личными INI/project/work/tmp, защитой общих настроек и журналом. Путь RUN печатается в выводе. Затем проверяется именно этот запуск:

```powershell
C:\Python312\python.exe -X utf8 -B bin\maxplus2_review_run.py temp_max_run\mp2_runs\ИМЯ_ИЗ_ВЫВОДА
```

Требуются MAX+plus II 10.0 в квалифицированной установке, Python и Frida. Корневой mp2build.ps1 относится к плоскому net_list и не является командой сборки этого проекта. Общие INI, реестр и чужие процессы не изменяются.

## Проверено для текущего src

После переименования top в SCROLL выполнена полная команда новой задачи: `rename_scroll_src_20261101_002`. Native-компиляция завершилась штатно, проверка изоляции — PASS (16573 события). Результат: **1342 LC, 4 EAB / 12032 бита RAM, Fmax TG42 45,04 МГц**. Все 13 входов привязаны к текущему src. Полные SOF и TTF побайтово совпадают со сборкой до смены имени top; опубликованный SCROLL.ACX также совпадает со всеми 59215 байтами её TTF. Таким образом, само это переименование не изменило аппаратный битстрим. Выходы и манифест — Build/SCSRC.

Первый запуск переименованного проекта (`rename_scroll_src_20261101_001`) задержался при завершении процесса и не принят. После отдельной успешной сборки он завершён как собственный процесс с проверкой PID, пути EXE и времени создания; получен FAIL, публикация из него не выполнялась. Guard/shared INI не менялись. Протокол — work/rename_scroll_20261101.

Историческая сборка после исправления переноса, до смены имени top: `transfer_repair_src_20261101_001`. Тогда верхний проект назывался SP2_1K30. Проверены привязки всех 13 входов, native-компиляция и `PASS_COMPILE_AND_OBSERVED_ISOLATION`. Результат: **1342 LC, 4 EAB / 12032 бита RAM, зарегистрированный Fmax TG42 45,04 МГц**. Выходные SOF/TTF и отчёты находятся в каталоге этого запуска.

**Битстрим текущего src отличается от SCAUTH31.** В тот момент, до смены имени top, единственное различие входов с принятой сборкой было следующим: пользовательское переименование AUDIO_CHS в AY_CHS (пять употреблений). В отдельной копии `work/transfer_repair_20261101/name_control` обратное переименование восстановило все прежние входы и полную побайтовую идентичность SNF/SOF/TTF. Контрольный запуск `transfer_repair_name_control_20261101_001` также прошёл изоляцию; его Fmax — 45,45 МГц. Рабочее пользовательское имя ради идентичности файлов не откатывалось.

Принятый ранее функциональный гейт включает 35598 обязательств по FF, RAM, пинам и обратной связи с негативными контролями. Для текущего заново размещённого битстрима этот гейт повторно не запускался. Для исправления переноса проверено соответствие всех входов принятому проекту с единственным согласованным различием имени. Native vendor functional simulator, CPU/BIOS/TITD и плата в этом исправлении не запускались; расчёт Fmax не является измерением внешних setup/hold/OE.

## Пакет и испытания на Sprinter

`../Build/SCAUTH31` сохранён без изменений: это ранее выпущенная сборка с именем AUDIO_CHS и своим SOURCE.ZIP/манифестом. Он остаётся самостоятельным согласованным пакетом; его нельзя описывать как побайтовый результат текущего src с AY_CHS. Новая публикация пакета при исправлении переноса не выполнялась.

На плате требуется проверять именно выбранный битстрим. Если TITD сама загружает встроенную конфигурацию, запуск игры после ручной загрузки ACX может вернуть эталонную прошивку. Нужно сохранить имя и хеш реально проверяемого файла.

Открыты испытания TITD, аппаратного скролла по обеим осям, крайних столбцов и нижней строки, ввода и PCM. Отдельная незавершённая задача — битмап, явно различающий 320/640, и шахматная карта описателей этих режимов.

## Переименование проекта и Git

01.11.2026 файлы src/SP2_1K30.TDF и src/SP2_1K30.ACF переименованы в src/SCROLL.TDF и src/SCROLL.ACF. В AHDL изменено только имя SUBDESIGN, в ACF — только имя CHIP; функциональные уравнения, память и параметры сохранены.

История перехода разделена на два коммита. Отдельный коммит `4d1534e` фиксирует только переименования с согласованными объявлениями SCROLL (R099). Следующий коммит содержит изменения авторского BASE→SCROLL, удаление лишних модулей и необходимые файлы сборки. Таким образом, содержательный diff SCROLL.TDF/ACF сравнивается с теми же файлами предыдущего коммита, а связь со старыми именами сохраняется в истории.

.vscode/tasks.json и файл рабочего пространства подпадают под пользовательский глобальный .gitignore, но явно включены в этот репозиторий как настройки проекта SCROLL. Глобальные правила ignore не менялись. bin/build_src.py и необходимые launcher/guard/reviewer также включены в репозиторий; для сборки на другой машине нужны Python с Frida и квалифицированная установка MAX+plus II, описанные выше.
